# 有界编辑合同：定点修改提示词（借鉴 `short-drama-image-prompts`）

> 本文件的场景是「**图已经出来了，只想改一处**」——不是重写整段，而是定点修改一张已生成的图。
> 它补上了七段式模板没覆盖的「迭代/改图」环节。核心纪律：**改图必须声明「改什么 + 保留什么」，且不能借改图偷偷篡改上游事实。**

---

## 一、两类修改

| 类型 | 是什么 | 产出 | 边界 |
|---|---|---|---|
| **对画面的 edit** | 改一张已生成图的局部（换件衣服、改一处伤） | `edit_delta` 提示词 | 只改画面，不执行图像编辑 |
| **对提示词本身的 revision** | 用自然语言改规格（把工作服换成深蓝） | 先提案 diff，确认后重写 | 不改写资产拥有的身份/变体事实 |

**两条都不能**改写 assets 拥有的身份 / 变体事实。若请求是「把这扇门移到另一面墙」但 Location 地理未变更，应发 assets/storyboard 的 revision request，而不是悄悄写进 edit。

---

## 二、Edit-delta 配方：四问缺一不可

每次定点修改，必须答清这四个问题，少一个就拒绝执行：

```
Target            改哪个 asset / 对象 / 区域？
Change            哪些有边界、可观察的变化？
Preserve          什么必须不变？
Continuity impact 影响到哪个已确认状态、哪些 shot 要同步？
```

### 1. Target（目标）

- 用 asset 编号和对象名绑定目标（如 `CHAR-001 梁大 的左袖口`），可复制正文用自然语言写清主体和区域。
- **「改背景」「让她更狼狈」过宽**——需要具体到新 View / 区域 + 可观察变化。
- 多个不相干的 target 默认拆成多个 edit，防止 preserve 集失焦。

### 2. Change（变化）

按「位置 + 方向 + 范围 + 程度 + 材质/色彩结果」写 delta：

> ✅「右袖肘部以下呈雨水浸湿后的深色，衣料贴合但无撕裂」
> ❌「衣服弄湿」

**不得补写未接受的伤势或剧情因果**——「加一道刀伤」若剧本里没有，就是越权。

### 3. Preserve（保持项，最容易被忽略）

先列最容易被误改的高价值事实，逐一点名：

- 面部 / 体态身份
- 未变的 Look 部件（脸、发型、身形、其他服装）
- 固定地理
- 道具轮廓与文字
- 构图 / 机位 / 光向
- 未选中的区域

**不要用「其他全部保持」代替边界思考**——它只允许作为已点名 preserve set 之后的概括收尾。

### 4. Continuity impact（连续性影响）

引用道具状态 / Look / View，或提出 owner revision；记录受影响的 prompt / shot / keyframe，**而不是在 edit 里成为新的连续性权威**。若无影响，明确写 `none` 及理由。

---

## 三、越权 edit 红线

三种情况**严禁**伪装成「局部提示词修订」：

1. **改身份**：`保持所有东西不变，把这个人换成另一个人`
2. **改固定地理**：`保持所有东西不变，把维修间改成豪华酒店大堂，再把后门移到左侧`
3. **改上游已确认事实**：伤口、道具状态、服装变体若还没在 make-spec / storyboard 里立档，不能靠 edit 补写

遇到这三种，路由回 owner（assets / storyboard），而不是写进 edit。

---

## 四、自然语言修订流程（用户不用懂内部字段）

用户说「把工作服换成深蓝，但保留脸和袖口油渍」，执行：

1. 读当前 asset 条目 + 对应 prompt；
2. 区分「提示词可改措辞」vs「资产 owner 才能改的事实」vs「含糊项」vs「连续性影响」；
3. 展示简短语义差异：**改前 / 改后 / 理由 / 保持项 / 影响 / 是否需上游修改**；
4. 展示新的可复制正文；
5. 确认后更新；拒绝时当前文件保持不变；
6. 列出需要同步检查的相关 shot / prompt，**不自动改用户没点名的文档**。

预览模板：

```markdown
### 提议修改 CHAR-001
- 深灰蓝工作服 → 深蓝工作服
- 保持：脸、服装剪裁、右袖口旧油渍的形状与位置、背景、构图、光向
- 影响：仅当前造型提示词；若 bible 还没有深蓝变体，先交 assets 修改

**新正文预览**
> ...
```

对「更有电影感」这类诉求，**不要擅自堆风格词**。给两三个互斥且可观察的候选（光比 / 构图 / 色彩关系），作为 `taste_option` 让创作者选。

---

## 五、失败征兆与完成检查

**失败征兆**（出现即返工）：
- 只改可复制正文，不核对 bible / make-spec；
- 差异只写「优化措辞」，没有语义影响和保持项；
- 在提示词层擅自改掉身份 / 地理 / 道具状态；
- edit 只有 Change、没有 Preserve；
- 发现冲突后自动覆盖人工修改。

**完成检查**：
- 上游事实请求已路由给正确 owner；
- Target / Change / Preserve / Continuity impact 四问都清楚；
- 差异预览可读、可拒绝，新正文可直接复制；
- 拒绝不改变当前文件，冲突不静默吞掉。
